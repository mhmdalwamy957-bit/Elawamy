# تحديث منظومة الحلاق — ElaWamy

هذا التحديث يكمل منظومة الحلاقة الموجودة بالفعل ولا يستبدلها. يضيف إدارة تشغيل المواعيد، تسجيل حضور العميل أو عدم حضوره، سجل تدقيق لهذه العمليات، ومؤشرات للتحصيل وتصدير يوم العمل.

## الوظائف الموجودة والمكملة

- حساب صاحب الصالون: إنشاء الصالون، بياناته وصورته وساعات عمله.
- إدارة الحلاقين: الإضافة، ساعات العمل وأيام الإجازة الأسبوعية، **إجازات خاصة بتواريخ محددة**، الصورة الشخصية، إيقاف الحلاق مؤقتًا، وكود الربط لمرة واحدة.
- إدارة الخدمات: الاسم والمدة والسعر وتفعيل/إيقاف الخدمة.
- الحجز: عرض المواعيد المتاحة وحجزها بقفل معاملاتي في الخادم.
- صفحة الحلاق: ربط الحساب، تعديل جدوله وصورته، متابعة حجوزات اليوم والمواعيد القادمة.
- لوحة التشغيل: عرض حجوزات يوم محدد، البحث والفلترة حسب الحالة، ملخص عدد المواعيد والتحصيل، وتصدير CSV.
- **تقرير مالي لفترة تختارها (حتى 31 يومًا):** قيمة الخدمات المنفذة، إجمالي التحصيل المؤكد من الحجوزات غير الملغاة، المستحق عن الخدمات المنفذة غير المحصّلة، وعدد الحجوزات والإلغاءات وعدم الحضور.
- تقسيم التقرير المالي حسب الحلاق والخدمة واليوم، مع تصدير تفاصيل الفترة إلى CSV. التقرير متاح لصاحب الصالون المسجّل فقط، والخادم يتحقق من ملكية الصالون ويحدّ عدد السجلات إلى 3000 سجل للطلب.
- تسجيل التحصيل النقدي، إلغاء الحجز، تسجيل تنفيذ الخدمة أو عدم حضور العميل.
- تذكير العميل يدويًا عبر WhatsApp من لوحة الصالون وصفحة الحلاق برسالة جاهزة تشمل الموعد والخدمة والسعر؛ لا يتم إرسال الرسالة تلقائيًا.
- كل عملية تحصيل أو إلغاء أو تحديث للحضور تكتب سجلًا في `barberShops/{shopId}/auditLog` مع الحساب والوقت.
- تسجيل الحضور لا يتم إلا بعد نهاية الموعد، ومن صاحب الصالون أو الحلاق المرتبط بذلك الحجز. حالة عدم الحضور تمنع تقييم ذلك الحجز.

## التحقق محليًا

من جذر المشروع:

```bash
node --check server/server.js
node --check public/js/barbers.js
node --check public/js/barber-schedule.js
node scripts/check-barber-booking.cjs
node scripts/test-barber-whatsapp.cjs
node scripts/test-barber-finance.cjs
node scripts/test-barber-closed-dates.cjs
# أو شغّل اختبارات منظومة الحلاقة معًا
npm run test:barber
```

## النشر بعد نجاح الفحوصات

أنشئ نسخة احتياطية أولًا. التقرير يستخدم فهرس `shopId` و`localDate` الموجود بالفعل، لذلك لا يضيف هذا التحديث فهرس Firestore جديدًا. يجب تحديث API والواجهة معًا حتى تعمل شاشة التقرير؛ نشر الواجهة وحدها لا ينشئ مسار API الجديد.

ابدأ بمعاينة للخادم من مجلد الخادم المرتبط بمشروع Vercel، واختبر مسار التقرير والحجوزات قبل الإنتاج:

```bash
cd server
npx vercel
```

بعد نجاح اختبارات المعاينة والتحقق من أن التطبيق متصل بالمشروع الصحيح، انشر API للإنتاج بقرار مقصود:

```bash
npx vercel --prod
```

ثم ارجع إلى جذر المشروع وانشر الواجهة:

```bash
cd ..
npx firebase-tools deploy --only hosting --project elawamy-8d7e9
```

لا تنشر قواعد Firestore أو تغيّر إعدادات XPay لهذا التحديث. لا ترسل قيم أسرار `.env` في المحادثات، ولا تنشر `--prod` قبل التأكد من أن معاينة API تعمل على المشروع الصحيح.

## فصل صفحات الحلاقة

أصبحت صفحات منظومة الحلاقة منفصلة في الواجهة:

- `/barbers` — استعراض الصالونات المتاحة.
- `/salon` — لوحة صاحب الصالون لإدارة البيانات والحلاقين والخدمات والحجوزات. عند فتح إعدادات صالون معيّن، يتم تمرير معرّفه إلى هذه الصفحة.
- `/barber-schedule` — الصفحة الشخصية للحلاق لربط حسابه وتعديل ساعات العمل ومتابعة مواعيده.
- `/barber-booking` — صفحة الحجز المستقلة للعملاء.

تم توحيد روابط التنقل لتصل إلى الصفحات الصحيحة. يحتفظ كل مسار بوظائفه الحالية، وتحتاج إدارة الصالون إلى تسجيل الدخول بحساب صاحب الصالون.
