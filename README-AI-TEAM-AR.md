# فريق العوامي AI — تكامل GitHub والمرحلة الثانية

## ماذا يفعل التحديث؟

- ينظم فريق التطوير في **8 مجموعات × 5 أدوار = 40 دورًا تخصصيًا**: المعمارية والمنتج، واجهات الويب، تطبيق الهاتف، الخادم وواجهات API، Firebase والبيانات، الأمان والخصوصية، الجودة والاختبارات، والتشغيل والإصدار.
- الأدوار الأربعون شخصيات تنسيق ومراجعة ضمن نموذج Gemini واحد، وليست 40 نموذجًا منفصلًا أو 40 اشتراكًا مدفوعًا.
- يقرأ فهرس ملفات المستودع عبر GitHub، ثم يحمّل حتى 16 ملفًا نصيًا الأكثر ارتباطًا بكل مهمة ضمن حد سياق محدد. الملفات الحساسة وإعداد Firebase العام المولّد مستثناة من سياق النموذج.
- بعد مراجعة التقرير، موافقة الأدمن تشغّل توليد التغيير، وتطبّق استبدالات نصية دقيقة أو تنشئ ملفات جديدة على فرع مستقل، ثم تفتح **Pull Request مسودة**.
- يمكن للأدمن رفض المقترح أو إعادة محاولة تجهيز PR عند فشل التوليد أو صلاحيات GitHub.

## حدود الحماية

- الفرع الأساسي الافتراضي هو `ai-team-bootstrap-20261125`، وليس `main`.
- الخادم يرفض `main` و`master` كفرع أساسي ما لم يُضبط `GITHUB_ALLOW_MAIN_BASE=true` صراحةً. لا تضبطه لهذا المشروع.
- لا يوجد دمج تلقائي ولا نشر إلى Firebase أو Vercel.
- لا يحذف الفريق ملفات. التعديل في الملف الموجود يتطلب نصًا قديمًا مطابقًا مرة واحدة بالضبط؛ إذا لم يتحقق ذلك يتوقف التنفيذ قبل كتابة الملفات.
- الحد الحالي خمسة ملفات لكل مهمة، وبحد أقصى 12 استبدالًا لكل ملف. إعدادات النشر وملفات الأسرار وملفات lock وقواعد Firestore محمية من التعديل الآلي.
- خادم Vercel لا يدّعي تشغيل الاختبارات. يرفق الفريق خطة الاختبار داخل PR، ويلزم تشغيل CI أو الاختبارات محليًا ومراجعتها قبل الدمج.
- ملفات المستودع تعامل كبيانات غير موثوقة؛ لا تتبع تعليمات مضمنة داخل ملفات الكود أو المستندات.

## متطلبات GitHub

أضف المتغيرات التالية في Vercel ضمن Environment Variables كـ **Secret** أو قيمة إعداد حسب نوعها:

- `GITHUB_TOKEN`: Fine-grained Personal Access Token خاص بالمستودع المحدد فقط.
- صلاحيات الرمز المطلوبة: **Contents: Read and write** و**Pull requests: Read and write**. صلاحية Metadata للقراءة تُمنح تلقائيًا عادةً.
- `GITHUB_REPOSITORY`: اختياري؛ الافتراضي `mhmdalwamy957-bit/Elawamy`.
- `GITHUB_BASE_BRANCH`: اختياري؛ الافتراضي `ai-team-bootstrap-20261125`.

لا تضع الرمز في ملفات المشروع أو الواجهة أو المحادثة. لا ترسله إلى أي شخص. أعد نشر Backend على Vercel بعد تغيير Environment Variables أو كود الخادم.

## تدفق العمل من لوحة الأدمن

1. افتح `/ai-team-admin.html` بحساب يحمل Firebase admin claim.
2. تأكد أن لوحة الحالة تعرض اتصال GitHub والفرع المعزول.
3. اكتب مهمة محددة. سيعرض التقرير عدد ملفات المستودع وعدد الملفات التي قرأ الفريق محتواها ومساراتها.
4. راجع التقرير. الرفض يسجل القرار ولا يغيّر المستودع.
5. الموافقة تنشئ فرعًا باسم `ai-team/task-...` وتفتح Draft Pull Request يستهدف الفرع المعزول.
6. راجع الملفات المتغيرة وخطة الاختبارات في GitHub. لا تدمج أو تنشر حتى تنجح الاختبارات وتراجع التغيير يدويًا.

## متغيرات الذكاء الاصطناعي

- `GEMINI_API_KEY`: مفتاح Gemini على الخادم فقط.
- `GEMINI_MODEL`: الافتراضي `gemini-3.8-flash` إذا كان متاحًا في مشروعك وحصتك.
- `OPENROUTER_API_KEY`: اختياري لمراجع مجاني ثانٍ.
- `OPENROUTER_REVIEW_MODEL`: الافتراضي `openrouter/free`، والكود يمنع اختيار نموذج لا يساوي `openrouter/free` أو لا ينتهي بـ`:free`.

توفّر النماذج المجانية وحصصها ليست مضمونة وقد تتغير. تشغيل 40 دورًا كشخصيات تنسيق لا يعني توفر 40 نموذجًا مستقلًا.

## فحوصات محلية

من مجلد المشروع:

```bash
node --check server/server.js
node --check server/ai-team-github.js
node --check public/js/ai-team-admin.js
npm run check
npm run test:barber
```

قد تحتاج بعض الاختبارات إلى ملفات إعداد تجريبية مثل `server/.env.example`، ويجب ألا تضع فيها قيمًا حقيقية.
